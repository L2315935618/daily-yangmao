# 「每日羊毛」部署指南（Cloudflare Pages + Worker）

- 版本：v1.0
- 前提：代码已推 GitHub（仓库名 `daily-yangmao`），本地 `astro build` 通过。

---

## 1. 链路总览

```
本地 Kylin（抓数据/开发）
   → git push → GitHub 仓库
      → Cloudflare Pages 自动构建（astro build）→ 线上静态站
浏览器搜索请求 → CF Worker (/api/search) → Coze API（Token 藏 Worker 里）
WorkBuddy 定时任务（每日 08:00）→ 抓数据 → push → 触发 Pages 重建
```

## 2. 分步清单

### Step 1 — GitHub 仓库

1. 创建私有/公开仓库 `daily-yangmao`（github connector 已连，可由我代建）。
2. `git remote add origin ... && git push -u origin main`。

- ✅ 验证：GitHub 网页能看到代码。
- ⚠️ 常见失败：Kylin 上 git 凭据未配 → 用 github connector 或 PAT。

### Step 2 — Cloudflare Pages 接入

1. 登录 dash.cloudflare.com → Workers & Pages → Create → Pages → Connect to Git。
2. 授权 GitHub，选 `daily-yangmao` 仓库。
3. 构建设置：
   - Framework preset: **Astro**
   - Build command: `npm run build`（或 `astro build`）
   - Build output directory: `dist`
   - Node 版本环境变量：`NODE_VERSION=22`
4. Save and Deploy。

- ✅ 验证：构建日志全绿，访问 `daily-yangmao.pages.dev` 能看到首页。
- ⚠️ 常见失败：Node 版本过低（Astro 要求 ≥18）→ 必须设 `NODE_VERSION=22`；依赖装不上 → 确认 `package-lock.json` 已提交。

### Step 3 — 自定义域名（可选，先跳过）

- Pages → Custom domains → 绑自有域名，CF 自动签发 HTTPS。
- 前期直接用 `daily-yangmao.pages.dev`。

### Step 4 — Worker 搜索代理（P1，Token 到位后做）

1. `npx wrangler init worker-search`，写代理：
   - 接收 `GET /api/search?keyword=xx`
   - 服务端读 `COZE_TOKEN`（`wrangler secret put COZE_TOKEN`，**绝不写进代码/前端**）
   - 转发 Coze API，返回 JSON，配 CORS 只允许本站域名。
2. Pages → Settings → Functions 绑定 Worker 路由 `/api/search/*`。

- ✅ 验证：`curl "https://daily-yangmao.pages.dev/api/search?keyword=纸巾"` 返回结果。
- ⚠️ 风险：Token 泄露 = 别人白嫖你的额度。前端代码、仓库、Issue 里都不能出现 Token。

### Step 5 — 定时数据更新自动化

- 由我（WorkBuddy）创建定时自动化：每日 08:00 执行「跑薅羊毛助手抓取 → 生成当日 JSON → commit & push」。
- 手动更新：老大随时说"更新羊毛数据"，我立即跑一次。
- ✅ 验证：次日看仓库有新的 `src/data/YYYY-MM-DD.json` 提交，线上内容已更新。
- ⚠️ 前提：`~/.coupon_search_config.json` + `COZE_TOKEN` 已在老大机器配好（**当前未配，是 A1 阻塞项**）。

## 3. 回滚

- Pages → Deployments → 选上一个正常构建 → Rollback。静态站回滚秒级完成。
