| 阶段 | 内容 | 产出 | 负责模型 |

## 2. 双模型定位（擅长场景 × 成本）

| 维度 | kimi-k3（现在用的） | deepseek-v4.1-flash |
|------|--------------------|---------------------|
| 定位 | 主力脑：理解、规划、排障 | 快手：批量、模板、杂活 |
| 擅长 | 需求分析、架构设计、文档撰写、复杂调试、多工具编排（git/部署/自动化）、代码审查 | 样板代码生成、单组件按图施工、样式微调、文案/示例数据批量产出、重复性改写 |
| 弱项 | 单价高，别拿它搬砖 | 长链路 agent 任务易跑偏，复杂状态逻辑、跨文件重构、部署排障别交给它 |
| 成本 | 高（按能力计价，用在刀刃上） | 低（flash 级，适合放开量用） |
| 上下文/工具 | 长任务稳，工具调用可靠 | 短平快任务性价比高 |

**一句话：k3 当架构师和验收员，flash 当施工队。**

## 3. 任务级分工表（S2~S5）

| 任务 | 模型 | 理由 |
|------|------|------|
| 数据 JSON Schema 定义、抓取脚本设计 | k3 | 结构错了全站返工 |
| 抓取脚本主体代码（调 search.py / call_bot.py、清洗、写 JSON） | flash | 逻辑直白、模板化 |
| 示例数据生成（30+ 条逼真羊毛条目） | flash | 批量产出，flash 性价比最高 |
| Astro 布局骨架（BaseLayout、Header、Footer、导航） | k3 | 全局结构，影响所有页面 |
| 羊毛卡片 / 比价表 / 引流组件（按已定的布局与数据规范施工） | flash | 规格已定，纯执行 |
| 首页 / 分类页 / 归档页组装 | flash | 组件拼页，机械活 |
| 响应式与样式细节微调 | flash | 反复改 CSS，量大 |
| Worker 搜索代理（含 Secrets、CORS、错误处理） | k3 | 涉密钥与安全，不能出错 |
| Lighthouse 问题诊断与修复决策 | k3 | 需要判断取舍 |
| git 提交、仓库创建、CF 配置、定时自动化创建 | k3 | 外部操作，谨慎 |
| 每次 flash 产出后的代码审查 | k3 | flash 干活，k3 验收 |

## 4. 切换规则（写死，照此执行）

1. **新任务先问：规格是否已明确？**
   - 明确（有文档/有示例/有现成结构）→ flash。
   - 不明确（要决策、要设计、要排查）→ k3。
2. **flash 连续 2 次产出不达标**（编译错、逻辑错、答非所问）→ 切回 k3，由 k3 修并补规格说明，再交还 flash。
3. **涉钱、涉密钥、涉外部发布**（Token、CPS 链接、push、部署）→ 一律 k3。
4. **文档/汇报类输出** → k3（要拿给施秋敏看的材料不能糙）。
5. **批量内容生成**（示例数据、文案改写、多平台条目）→ flash。

## 5. 给老大的使用建议

- 当前会话（k3）：确认文档、搭骨架、定数据规范、最终审查、部署上线。
- 开 S3 页面施工时：可切到 deepseek-v4.1-flash，把「PRD §4-§6 + 数据 Schema + 组件清单」喂给它按件施工；出问题随时切回 k3 兜底。
- 每次切换模型，把 `docs/01-需求文档.md` 路径告诉它，让它先读文档再动手。
